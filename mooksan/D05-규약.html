규약

코드 · 문서 · 커밋. 지키기 쉬운 것만 규약으로 만든다.

1. 코드

1-1. 언어와 주석

  • 한국어 주석. 이 프로젝트의 도메인 용어가 한국어다(무감각·안전지대·편입·홈베이스)
  • 주석은 왜를 쓴다. 무엇을 하는지는 코드가 말한다
// ✅ 뛰면 카운터가 거짓말한다 — 셈이 어긋난 줄 모르게 하는 것이 목적
// ❌ S.unit을 1 증가시킨다
  • 도메인 용어는 한국어 그대로 변수명에 쓰지 않는다. 대응 영단어를 고정한다
한국어코드
무감각numb
안전지대haven
편입absorb
조력자helper
챕터chapter
부품part

1-2. 상태

  • 전역 상태는 S 하나. 여러 개 만들지 않는다
  • S는 직렬화 가능해야 한다. 함수·DOM 참조·Image 객체를 넣지 않는다

→ 세이브·하네스·재현이 전부 여기 달려 있다 → [[95-하네스]]

  • 렌더 함수는 상태를 바꾸지 않는다. draw*()는 읽기 전용

1-3. ★ 난수

Math.random() 직접 호출 금지. 예외 없다.

const rng = mulberry32(seed);   // 시드 고정 PRNG

재현이 안 되면 버그를 두 번 볼 수 없다. 이번 세션에 실제로 겪었다.

1-4. 파일 크기

  • 한 파일 400줄을 넘으면 쪼갠다
  • 현재 play/index.html은 700줄이고 이미 한계를 넘었다 → 0단계에서 분리

1-5. 렌더 순서

타일을 열 단위로 그릴 때, 뒤 열이 앞 열의 오버레이를 덮는다. 문패·표지·프롭처럼 타일 경계를 넘는 것은 별도 패스로 그린다.

실제 사고: 문패를 문 왼쪽 칸에서 그렸더니 다음 칸의 벽 타일이 오른쪽 절반을 덮었다.

2. 문서

→ 체계 전체는 [[D00-문서체계]]

  • 정본 1개 원칙 — 같은 사실은 한 문서에만. 요약도 복사다
  • 밸런스 수치는 문서에 쓰지 않는다 — 데이터 파일에만
  • 폐기는 이유와 함께 남긴다 — 문서 맨 아래 「폐기한 것」 절
  • 낡으면 즉시 배너 — 갱신할 시간이 없어도 배너는 단다

3. 커밋

커밋 메시지는 결정 기록이다. git log가 사실상 ADR 초안 역할을 하고 있다.

<한 줄 요약: 무엇을 왜>

<바뀐 것 — 목록>
<폐기한 것 — 이유 포함>
<검증한 것 — 어떻게 확인했나>
  • 무엇을 고쳤는지보다 왜 고쳤는지를 쓴다
  • 설정을 버렸으면 버린 이유를 반드시 남긴다
  • 배포가 포함되면 검증 방법(해시 대조 등)을 적는다

4. 배포 전 필수 확인

→ 절차 전체는 [[D50-빌드]] · 함정은 [[D99-함정]]

  1. python3 build.py 성공
  2. 로컬 해시와 라이브 해시 대조 — 「고쳤는데 안 고쳐졌다」의 90%가 캐시다
  3. rsync --delete 를 쓸 때 무엇이 지워지는지 먼저 본다

(실제로 play/ 를 지울 뻔했고 pre-commit 훅이 막았다)

  1. 스크린샷 회귀 (하네스 도입 후)
