함정

실제로 당한 것만 적는다. 고치기 전에 적는다 — 고치고 나면 사소해 보여서 안 적게 된다.

에셋

★ LimeZu 캐릭터 시트 블록 순서

Characters_16x16/*.png의 24프레임은 [0=오른쪽, 1=뒤, 2=왼쪽, 3=정면] 이다. 흔한 [아래, 위, 왼, 오른] 가정이 틀렸다.

const DIRROW = {0:3, 1:2, 2:0, 3:1};   // 게임 dir(아래/왼/오른/위) → 시트 블록

판정법 — 정면만 눈 2개 + 좌우대칭, 뒤는 피부 픽셀 0, 옆은 눈 1개. 프레임 영역은 y=32..63, 프레임 폭 16.

증상: 아래를 보는데 옆모습이 나온다. 사용자가 먼저 발견했다.

리컬러는 부위(y좌표) 기준으로

색 키 매핑만으로는 모자와 상의가 같은 색이라 함께 바뀐다. 스카우트 → 교복 리컬러 기준: y≤17 모자→검은 단발 / 18~23 얼굴·옆머리 / 24~25 흰 칼라 / 26~ 남색 교복

라이선스

편집·게임 내 사용 가능 / 재판매·에셋 재배포 금지 / 크레딧 필수. 원본 시트를 그대로 올리지 않는다. 사용분만 슬라이스해서 배포하고 하단에 크레딧을 표기한다.

렌더

★ 뒤 열이 앞 열의 오버레이를 덮는다

타일을 열 단위 루프로 그릴 때, 타일 경계를 넘는 요소(문패·표지·프롭)는 별도 패스로 그려야 한다.

증상: 명판이 절반만 보이고 글자가 잘림. 원인은 다음 열이 그리는 벽 타일이 명판 오른쪽을 덮은 것.

HUD는 뷰포트가 아니라 캔버스에 붙인다

position:fixed + 뷰포트 기준이면 창 크기에 따라 HUD가 게임 화면에서 떨어져 나간다. 캔버스와 같은 비율의 프레임 안에 넣거나, 캔버스에 직접 그린다.

픽셀 아트 축소를 허용해야 한다

Math.max(1, ...)로 스케일 하한을 1로 잡으면 뷰포트가 캔버스보다 좁을 때 잘린다.

배포

★ 캐시 — 「고쳤는데 안 고쳐졌다」의 90%

GitHub Pages는 즉시 반영되지 않는다. 로컬 해시와 라이브 해시를 대조한다.

L=$(shasum -a1 play/index.html | cut -c1-12)
V=$(curl -s "$URL?cb=$RANDOM" | shasum -a1 | cut -c1-12)
[ "$L" = "$V" ] && echo 반영됨

★ 파이프라인 종료 코드

verify.py | tail -3 && deploy      # ❌ tail의 종료 코드(0)가 && 를 통과시킨다
verify.py > /dev/null 2>&1 && deploy   # ✅

실제로 검증 실패한 상태로 배포한 적이 있다.

rsync --delete

rsync -a --delete site/ mooksan/ 은 mooksan/play/ 처럼 site에 없는 형제 디렉터리를 지운다. pre-commit 훅이 막아줬지만, 훅이 없는 곳에서는 그대로 날아간다. 무엇이 지워지는지 먼저 확인한다.

커밋 메시지에 한글 따옴표

heredoc으로 넘기면 셸이 깨진다. git commit -F 파일을 쓴다.

로직

되돌아오면 안 되는 값은 Math.max로 누적

외부 경과 시간처럼 단조 증가여야 하는 값을 매번 재계산하면 되돌아온다.

S.outMin = Math.max(S.outMin, computed);

시드 없는 난수

Math.random()이 게임 로직에 들어가면 버그를 재현할 수 없다. → [[D05-규약]]

도구

브라우저 패널 스크린샷

패널이 좁으면(275 CSS px 등) 캔버스가 잘리고, resize_window 후 컴포지터가 옛 스케일에 묶이는 경우가 있다. navigate → resize → JS로 상태 세팅 → 스크린샷 순서가 가장 안정적이다. HUD를 잠시 숨기고 찍으면 렌더만 따로 볼 수 있다.

문서 site와 게임 play는 다른 빌드다

build.py는 docs/ 만 만든다. play/ 는 별도 rsync다. 둘을 한 번에 검증하지 않는다.
